B1a. Ollama advisory service — setup review, 2026-10-06

Official Ollama ARM64 release 0.35.1 was installed in the development Jetson user's home directory because non-interactive sudo was unavailable. The enabled systemctl --user service responds at http://127.0.0.1:11434/api/version and /api/tags. Its listener was verified as localhost-only. This is a user-session service, not a verified unattended boot service; operation after logout or reboot remains a separate validation gate.

No unrestricted 0.0.0.0 listener or wildcard CORS override was configured. Ollama exposes an HTTP API; it is not the crawler WebSocket interface. A backend on the same Jetson can query it locally. Access from another Jetson or workstation requires an authenticated tunnel or a separately validated, restricted proxy. Cloud features are disabled, and no dashboard, sensor, or motor-control code was wired to the service.

The qwen2.5:3b download completed successfully; the local /api/tags endpoint listed its Q4_K_M model weights (approximately 1.93 GB), while /api/ps confirmed that no model was loaded. At the setup check, the host had approximately 7.3 GiB RAM, less than 1 GiB available, and no swap. The service is limited to 768 MiB of host memory, one loaded model, and one concurrent inference request. Downloading model weights does not validate inference; loading or generating with the requested qwen2.5:3b is deferred until memory headroom is established and appropriate limits are reviewed. The GPU discovery log reported the Orin GPU through CUDA 13, but no model inference or acceleration benchmark has been verified. Model output remains advisory only and must never authorize motion or bypass STM32 safety enforcement.

7. Dashboard and telemetry integration status

The UJAALLC-4WIFI dashboard contains a CRAWLER-01 [JETSON #2] panel and a dedicated /ws/crawler/{crawler_id} WebSocket. The gateway validates the crawler ID and required telemetry fields (pose, heading, battery, LIPS target/range, and STM32 RPM, motor temperature, and E-stop state), retains the latest valid packet, and relays connection and telemetry messages to browser clients. The UI labels a disconnected crawler offline rather than treating cached values as live.

Safety and scope: This gateway is a display/telemetry integration. A crawler panel or spatial advisory coordinate is not a dispatch implementation, surveyed waypoint, safety-rated stop, or permission to move. No crawler motion command path is documented as implemented in this plan.
